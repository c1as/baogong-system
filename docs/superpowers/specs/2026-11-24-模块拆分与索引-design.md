# 报工系统：模块拆分 + 索引 设计方案

- 状态：待评审
- 日期：2026-11-24
- 适用代码：`D:\账本\报工系统`（Web 主库，v2.7 待发版基线）
- 目标读者：项目维护者、参与的 AI 编码会话

## 1. 背景与目标

当前前后端主体都是单文件：`public/app.js` 约 4000 行、`public/api.php` 4113 行、`public/style.css` 3059 行。AI 编码时定位一个问题往往要读整个文件，单次任务上下文消耗 4 万 token 量级。

本方案的目标是**在不改变任何运行行为、不引入构建工具的前提下**：

1. 按业务域把前后端拆成 300–700 行的文件；
2. 建立"域 → 文件 → 职责"的索引，让 AI 先读索引再定向读文件；
3. 把典型维护任务的读取量从约 4000 行降到约 700 行，上下文消耗降低 60% 以上。

### 量化目标

| 指标 | 现状 | 拆分 + 索引后 |
|---|---|---|
| 改「零件列表」需读的代码 | 可能整个 app.js（约 4.3 万 token） | `views/parts.js` 约 150 行 + 索引（约 6 千 token） |
| 改单个接口 | 可能整个 api.php（约 4.3 万 token） | `actions/parts.php` 约 400 行（约 5 千 token） |
| 单文件最大行数 | 4113 | ≤ 700 |

## 2. 设计原则

1. **零构建**：不引入 Vite/Webpack/esbuild，`index.html` 顺序加载经典脚本，`php -S` 直接跑。
2. **不改行为**：纯搬移，函数名、接口路径、返回结构、数据库结构、`plugins/` 协议全部不变。
3. **依赖单向**：`core` ← `views/features` ← `shell`；`actions` → `lib`；反向依赖一律禁止。
4. **粒度有下限**：单个文件 300–700 行；低于 150 行的不单独建文件（防碎片化）。
5. **索引自动生成**：只维护文件头注释，索引由脚本产出，禁止手写行号。
6. **经典脚本全局命名空间**：`window.App = { core, shell, ui, views, features }`，不使用 ES Module（兼容旧版 Android WebView）。
7. **每阶段可独立回滚**：一次提交只做一层，回归通过再进下一层。

| 2984–4113 44 个 action 分支 | `actions/*.php` + `$ACTIONS` 表 | 每个 case 搬成一个 `act_*` 函数 |

路由表（同时是索引，改 action 必须改表，结构上不会失同步）：

```php
$ACTIONS = [
    'parts.list'   => ['parts',   'parts_list'],
    'report.create'=> ['reports', 'report_create'],
    'backup.create'=> ['data',    'backup_create'],
    // …共 44 项
];
```

- 分支体搬移时只做两件事：`break;` 改成 `return;`；把 `$db/$body` 等前置逻辑保留在函数内。
- 每个 action 文件只 `require_once` 依赖的 `lib/*.php`，由 `api.php` 统一按需加载。
- `header()/exit` 语义保持不变，CSV/JSON 下载与 PDF Range 响应原样迁到 `actions/data.php`、`actions/images.php`。

## 6. 索引体系（三种形态）

### 6.1 文件头注释（唯一需要人工维护的东西）

JS：

```js
/* 模块: views/parts
   路由: #/parts
   职责: 零件列表、搜索、图纸弹窗、导入入口
   依赖: core/api, core/model, features/image, features/csv
   导出: App.views.parts = { render }
   注意: 图纸查看复用 features/pdf 的 iframe 复用逻辑 */
```

PHP：

```php
/* 模块: actions/reports
   Action: reports.list reports.get report.create report.update report.delete
   职责: 报工单读写与明细联动
   依赖: lib/repo lib/validate lib/image lib/query
   注意: 创建/更新后需同步 orders 冗余字段 */
```

### 6.2 自动生成模块地图

`tools/gen-index.mjs`（约 50 行，Node 直接跑，无依赖）：

- 扫描 `public/js/**/*.js`、`public/lib/*.php`、`public/actions/*.php` 的头部注释；
- 输出 `docs/模块索引.md`：`| 域 | 文件 | 职责 | 依赖 |`，≤100 行；
- 命令：`node tools/gen-index.mjs`；发版前跑一次，结果随提交入库。

### 6.3 仓库根 `AGENTS.md`（AI 第一入口）

```markdown
# 报工系统
- 前端：public/js（views=页面，features=能力，core=工具），单文件 ≤700 行
- 后端：public/api.php 仅路由；业务在 actions/*，通用在 lib/*
- 改功能前先读 docs/模块索引.md
- 回归：node work/api-test.mjs（接口 36 例）+ 7 个页面手工/E2E
- 部署与备份见 部署说明.md；禁止引入构建工具
```

## 7. 兼容性与约束

| 事项 | 约束 |
|---|---|
| 浏览器 | 不使用 ES Module 与可选链等较新语法，保持在 ES2017 以内；手机端 390px 必须正常 |
| 加载顺序 | `index.html` 显式按序加载，`defer` 保持；任一脚本 404 会导致白屏，发版前用脚本核对全部 200 |
| 缓存 | 所有脚本/样式 `?v=2.8`，与设置菜单版本号同步 |
| PHP | 无 Composer/无自动加载，`require_once __DIR__ . '/lib/xxx.php'`；全局函数保持 `bg_` 前缀防冲突 |
| 插件 | `plugins/*` 目录、`plugin.json` 协议、`handler.php` 调用方式完全不动 |
| 数据 | `data/`、SQLite schema、备份格式不动 |
| 部署 | `.gitlab-ci.yml` 的热更新打包路径 `public/` 不变，新增子目录自然包含 |

## 8. 回归与验收

**每阶段结束必须全绿：**

1. 接口：`work/api-test.mjs` 36 例全通过（覆盖登录、零件/订单/报工 CRUD、导入导出、统计、附件、插件）。
2. 页面：登录 → 零件 → 零件表单 → 订单 → 报工 → 统计 → 设置/插件 → PDF 查看，8 个场景无控制台错误。
3. 静态资源：`index.html` 引用的每个 JS/CSS 返回 200，无 404。
4. 数据完整性：`health` 返回 1034 零件 / 3000 报工 / 3000 订单（预览库基线）。
5. PDF：`api.php?action=image&f=…pdf` 全量 200、Range 返回 206。
6. 移动端：390px 下顶栏齿轮、报工统计主标题、PDF 缩放与拆分前截图一致。
7. 索引：`node tools/gen-index.mjs` 生成结果与仓库内 `docs/模块索引.md` 无差异。

## 9. 明确不做

- 不拆 `style.css`：AI 极少整读 CSS，拆分收益低、回归成本高（后续若超过 5000 行再议）。
- 不引入构建工具、TypeScript、框架。
- 不改任何接口路径、返回字段、数据库结构、插件协议。
- 不做行号索引、不做手写函数清单。
- 不顺手改业务逻辑或修 bug（发现的问题单独记录，另开任务）。

## 10. 实施顺序

| 阶段 | 内容 | 提交粒度 |
|---|---|---|
| P0 | `AGENTS.md` + 文件头注释 + `tools/gen-index.mjs` + `docs/模块索引.md` | 1 次提交，纯文档/注释，零逻辑风险 |
| P1 | 后端 `lib/*.php`（纯函数搬迁，`api.php` 保留路由与 case） | 1–2 次提交 |
| P2 | 后端 44 个 case → `actions/*.php` + `$ACTIONS` 表 | 1 次提交 |
| P3 | 前端 `core/`、`shell/`、`ui/`、`features/` | 1–2 次提交 |
| P4 | 前端 `views/*`（一次一个页面，拆完跑该页 E2E） | 每页 1 次提交 |
| P5 | 版本号升 `v2.8`、更新 README/部署说明、重跑全部回归 | 1 次提交 + 标签 |

## 11. 风险与回滚

| 风险 | 应对 |
|---|---|
| 搬移漏函数导致白屏/500 | 每阶段跑 36 例接口回归 + 8 场景页面；出错按阶段 `git revert` 单次提交 |
| 脚本加载顺序错误 | `index.html` 顺序固定并在 P5 用脚本校验 200 + 控制台无错 |
| 手机端缓存混合新旧文件 | 统一 `?v=2.8`，发版说明里要求强制刷新 |
| 索引与代码漂移 | 索引由头部注释生成，CI/发版前比对差异 |
| 拆分期间并行改功能 | 拆分分支冻结功能开发，或功能改动先合并再拆 |

数据库、`data/`、部署脚本均不涉及，回滚不影响线上数据。
