## 1. 项目概述

面向机加工车间的轻量化计件报工系统。单人使用、内网部署，管理零件与工序单价、订单、报工记录，自动核算金额，并提供统计、导出、快照备份与拍照识别。

设计目标：

- **零外部依赖**：不依赖 Docker、Node、数据库服务；PHP + SQLite 即可运行。
- **单文件后端**：全部接口集中在 `public/api.php`，便于拷贝部署与回溯。
- **数据即文件**：数据库、图片、快照都在 `data/` 下，按目录分型存放，直接复制目录即可迁移。

## 2. 功能清单

| 模块 | 能力 |
| --- | --- |
| 零件管理 | 图号唯一、名称/材料/库存/备注、一零件多工序多单价、每道工序可填「工序说明」、CSV 批量导入导出（最多 9 道工序）、图片封面、多张图纸（图片/PDF） |
| 订单管理 | 订单号自动生成（`PO+日期-序号`）、按零件+工序、记录总数量与日期 |
| 报工录入 | 多明细、选零件带出工序/单价、金额自动计算、订单可留空自动建单、多张附件 |
| 拍照识别 | 识别插件把报工单照片转成日期 + 明细；结果面板支持点选原文手动填充 |
| 报工记录 | 日期范围筛选、关键字搜索、分批加载、CSV 导出 |
| 报工统计 | 日期范围 + 订单多选 + 零件多选 + 关键字，明细表分批加载 |
| 数据量统计 | 条数、数据库/图片/快照占用、年度分布 |
| 数据备份 | 手动/自动快照（带备注）、恢复（恢复前自动再存）、下载、删除、JSON 导入导出 |
| 访问控制 | `app.env` 单一访问密码，登录失败节流 |
| 移动端 | 手机底栏导航、自适应窄屏 |

## 3. 技术架构

```
浏览器（原生 HTML/CSS/JS，无构建）
        │  fetch JSON
        ▼
public/api.php（PHP 8.x 单文件后端，action 路由）
        │  PDO
        ▼
data/db/baogong.sqlite（SQLite，WAL）
data/images/{parts,attachments,drawings}（零件图 / 报工附件 / 零件图纸）
data/snapshots（VACUUM INTO 快照）
```

- 前端：`index.html` + `app.js` + `style.css`，hash 路由，无框架。
- 后端：`api.php` 入口，`lib/net.php` 负责服务器出网、插件自检与连接测试。
- 存储：SQLite 四张表；图片与快照以文件形式落盘。
- 数据加载：首屏只取元信息（`bootstrap`），列表 / 统计 / 导出由后端 SQL 分页与合计；下拉改为远程搜索，详情按 id 查询。`state` 接口保留但前端不再调用。

## 5. 数据模型

SQLite 文件：`data/db/baogong.sqlite`（WAL 模式，运行时出现 `-wal` / `-shm` 属正常）。

### parts（零件）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | UUID |
| no | TEXT UNIQUE | 图号（必填、唯一） |
| name | TEXT | 名称 |
| material | TEXT | 材料 |
| note | TEXT | 备注 |
| stock | REAL | 库存 |
| image | TEXT | 图片相对路径，如 `parts/固定块.jpg` |
| processes | TEXT | JSON 数组 `[{name, desc, price}]`，desc 为工序说明 |
| drawings | TEXT | JSON 数组 `[{path, name, type}]`，零件多张图纸（图片/PDF）；旧库启动时自动加列 |
| created_at / updated_at | TEXT | ISO 时间 |

### orders（订单）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | UUID |
| no | TEXT UNIQUE | 订单号 `PO20261120-01` |
| date | TEXT | 日期 `YYYY-MM-DD` |
| part_id / part_no / part_name | TEXT | 冗余的零件信息 |
| process | TEXT | 工序 |
| qty | REAL | 订单数量 |
| note | TEXT | 备注 |
| created_at / updated_at | TEXT | |

### reports（报工单）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | UUID |
| no | TEXT UNIQUE | 单号 `BG20261120-01` |
| date | TEXT | 日期 |
| worker | TEXT | 报工人 |
| workshop | TEXT | 车间 |
| note | TEXT | 备注 |
| order_id / order_no | TEXT | 首条明细的订单（兼容字段） |
| images | TEXT | JSON 数组，附件相对路径如 `attachments/20261120-001.jpg` |
| created_at / updated_at | TEXT | |

### report_items（报工明细）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 自增 |
| report_id | TEXT | 所属报工单 |
| part_id / part_no / part_name | TEXT | 零件 |
| process | TEXT | 工序 |
| qty / price / amount | REAL | 数量 / 单价 / 金额 |
| order_id / order_no | TEXT | 行级订单 |
| sort | INTEGER | 行序 |

索引：`reports(date)`、`report_items(report_id/order_id/part_id)`、`orders(date)`。

## 6. 接口一览

统一入口：`api.php?action=<动作>`。POST 使用 JSON 请求体，响应 JSON。

| action | 方法 | 说明 |
| --- | --- | --- |
| `bootstrap` | GET | 首屏元信息（auth / 计数 / 版本 / 配置） |
| `parts.list` / `parts.search` / `parts.get` / `parts.match` | GET | 零件分页列表 / 搜索 / 详情 / 下拉匹配 |
| `state` | GET | 全量数据（保留兼容，前端不再调用） |
| `part.create` | POST | 新增零件（含图片 dataURL、图纸列表） |
| `part.update&id=` | POST | 修改零件；改名同步零件图与图纸文件名 |
| `part.delete&id=` | GET | 删除零件及其图片、图纸 |
| `part.drawing.remove&id=` | POST | 删除单张零件图纸 |
| `part.stock` | POST | 只更新库存 |
| `part.import` | POST | CSV 批量导入零件 |
| `order.create` | POST | 新建订单（单号自动生成） |
| `order.update&id=` / `order.delete&id=` | POST/GET | 修改 / 删除订单 |
| `report.create` | POST | 新建报工单（含 `newImages`） |
| `report.update&id=` | POST | 修改报工单；附件增量保存 |
| `report.delete&id=` | GET | 删除报工单及附件 |
| `export.csv` | GET | 明细 CSV 导出（支持 from/to） |
| `export.json` | GET | 全量 JSON 备份 |
| `restore` | POST | 从 JSON 备份恢复（恢复前自动快照） |
| `backup.list` | GET | 快照列表与占用 |
| `backup.create` | POST | 创建快照（可带备注） |
| `backup.restore` | POST | 恢复指定快照（恢复前自动再存） |
| `backup.delete` | POST | 删除快照 |
| `backup.download&id=` | GET | 下载快照 `.sqlite` |
| `data.stats` | GET | 条数、数据库/图片/快照占用、年度分布 |
| `plugins.list` | GET | 插件清单与设置（密码回显 `********`） |
| `plugin.save&id=` | POST | 保存插件启用状态与设置 |
| `plugin.invoke&id=` | POST | 用图片调用识别插件 |
| `plugin.check&id=` | GET | 插件自检（API 链接测试） |
| `net.check` | GET | 服务器出网测试 |
| `image&f=` | GET | 读取图片（相对路径，如 `parts/固定块.jpg`） |
| `login` / `logout` | POST/GET | 登录 / 退出 |

错误统一返回 `{"error": "..."}` 与对应 HTTP 状态码。

## 7. 前端结构

`public/app.js` 单文件，按以下顺序组织：

1. **基础工具**：`$` / `$$`、`esc`、`money`、`fmtQty`、`fmtBytes`、`debounce`。
2. **日期范围**：`RANGE_PRESETS`、`rangePresetValue`、`resolveRange`、`rangeFilterHtml`、`setupRangeFilter`；预置范围每次打开按当天重算。
3. **全局状态**：`state`（parts/orders/reports/plugins/auth/imageBase）与各列表的查询、分页游标。
4. **图标**：内联 SVG `PATHS` + `icon()`。
5. **页面**：`viewParts`、`viewPartForm`、`viewOrders`、`viewOrderForm`、`viewReports`、`viewReportForm`、`viewStats`、`viewDataStats`、`viewSettings`。
6. **识别面板**：`renderOcrResult`、`pushItemRow`，识别结果可点选原文手动填充。
7. **数据备份**：`openBackup`、`loadSnapshots`。

约定：

- 列表统一「本地过滤 + 分批渲染」：零件 100/批、统计 100/批、订单 100/批、报工 50/批，底部「加载更多」。
- 搜索框统一 220ms 防抖，回车不刷新页面。
- 图片地址统一走 `imgUrl()`，对名称做 `encodeURIComponent`，兼容中文文件名。
- 路由：`#/parts`、`#/parts/new`、`#/parts/<id>/edit`、`#/orders`、`#/reports`、`#/reports/new`、`#/stats`、`#/data`、`#/settings`。

## 8. 文件存储规则

| 内容 | 位置 | 命名 |
| --- | --- | --- |
| 数据库 | `data/db/baogong.sqlite` | 固定 |
| 快照 | `data/snapshots/` | `db-YYYYMMDD-HHMMSS-xxxx.sqlite` |
| 零件图 | `data/images/parts/` | 零件名称（非法字符替换为 `-`，重名追加 `-2` / 短哈希） |
| 报工附件 | `data/images/attachments/` | `YYYYMMDD-NNN`（上传日期 + 当天序号） |

- 数据库与图片字段保存**相对路径**（`parts/xxx.jpg`、`attachments/xxx.jpg`），读取时依次在 `parts/`、`attachments/`、旧版 `images/` 根目录查找，兼容历史数据。
- 零件改名时同步重命名图片文件；删除零件/报工时清理对应文件。
- 旧版扁平目录在首次请求时自动迁移（db 文件、`backups/`、`images/` 根目录文件），完成后写入 `data/.storage-v2`，不重复执行。

## 9. 配置

`app.env`（模板见 `app.env.example`）：

| 键 | 说明 |
| --- | --- |
| `APP_PASSWORD` | 访问密码；留空表示不启用登录 |
| `DATA_DIR` | 数据目录绝对路径；留空使用 `报工系统/data` |

`data/plugins.json`：插件启用状态与设置，由设置页保存；`password` 类型字段不会回显明文。

## 10. 本地运行与部署

```powershell
# 本机预览
php -S 127.0.0.1:8080 -t public
```

- 需要 PHP 8.x，启用 `pdo_sqlite`；拍照识别另需 `curl`、`openssl`。
- `data/` 需给 Web 用户读写权限；`open_basedir` 不得限制该目录。
- 群晖 Web Station 完整步骤见 [部署说明.md](../部署说明.md)。

## 11. 开发约定

- **版本号**：每次需求更新提升版本号，侧栏 `vX.Y · 数据保存在服务器` 与 `index.html` 静态资源参数 `?v=X.Y` 同步修改。
- **归档**：完成后打包到 `报工系统-历史版本/baogong-v<版本>-<日期>.zip`，只含 `public/`、README、部署说明、模板、`app.env.example`，不含 `data/`。
- **版本记录**：在 `README.md` 的版本表中追加一行，旧版本行补上归档路径。
- **编码**：源文件 UTF-8；`.php` / `.js` / `.md` 使用中文注释与文案。
- **错误处理**：后端异常统一走 `bg_fail()`；前端 `api()` 捕获后 `toast` 提示，401 跳登录。
- **安全**：图片文件名白名单校验；快照文件名严格正则；插件脚本仅允许由 `api.php` 引入，直接访问返回 403。
