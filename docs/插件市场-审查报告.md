### 4.2 失败项（3 处，均为 ENGINEER 级）

| ID | 问题 | 文档内证据 | 影响 |
| --- | --- | --- | --- |
| **E1** | **checkout `ref: plugin` 与正文"检出 tag 对应提交"矛盾** | §4.2 Step① 写明"检出 tag 对应提交"；但 §4.3 YAML L142–146 为 `actions/checkout@v4` + `ref: plugin`，检出的是 plugin 分支 **HEAD** 而非 tag 指向的 commit | 发布历史 tag 或 tag 非最新 HEAD 时，③ 清单校验与 ⑤ 打包针对的是分支最新代码（可能版本已变），导致校验失败或打包错版本。应改为默认检出 `$GITHUB_SHA`，另单独 `fetch origin plugin` 供祖先链校验 |
| **E2** | **upsert 条目字段缺失，与 §5.4 及索引 schema 矛盾** | §5.4 步骤2 要求"从 plugin.json 同步 name/version/description/author/capabilities/entry/check/defaultEnabled/settings"；但 §4.3 YAML L241–246 的 jq ENTRY 仅生成 `id/version/tag/releasedAt/package{name,url,sha256,size}` | 按此 YAML 落地，索引条目缺少 name/capabilities/entry/check/defaultEnabled/settings，手机端详情页、能力标签、hasCheck（自检按钮）、默认启用状态均无法渲染，与 §5.4 承诺不一致 |
| **E3** | **未处理索引文件首次不存在，与 §5.4 步骤1矛盾** | §5.4 步骤1："首次发布若不存在则由 CI 创建骨架（schema/generatedAt/source/空 plugins）"；但 §4.3 YAML L247–251 直接 `jq ... plugins-index.json > .tmp`，文件不存在时 jq 报错 | 存量 6 插件"首版入库"（规范 §8、架构 T08）无法按此 YAML 完成，首次发布必然失败 |

**维度 4 结论：FAIL。** E1/E2/E3 均为"设计正文承诺正确、YAML 片段未落实"的内部不自洽，非纯措辞，需工程师修正 YAML 后重新核验。
