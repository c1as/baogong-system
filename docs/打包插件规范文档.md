## 1. 文档目的与适用范围

### 1.1 目的

本文规定"把一个插件打成合法 zip、使其能被插件市场接受"的**全部打包约束**。读者照本文逐条执行，即可独立产出一个满足市场校验（架构文档 A.3.4 / A.5）、可被 CI 自动发布、可被手机端热更新安装的安装包。

本文**只讲"包怎么打"**；"打完如何发到市场、CI 如何运作、失败如何回滚"见配套文档《打包工作流文档》。

### 1.2 适用范围

| 项 | 说明 |
| --- | --- |
| 适用对象 | 插件开发者、插件包打包人员、对存量插件做增量发布的人 |
| 适用产物 | 发布到 `c1as/baogong-system` 的 `plugin` 分支 Release 的 `.zip` 插件包 |
| 不适用 | 服务端程序热更新包（`web-v*` tag，走 `.gitlab-ci.yml`/App 仓 `build-release.yml`，与本规范无关）。边界说明：本规范产出的 zip 由市场安装到 `data/market-plugins/<id>/`；插件源码放 `plugins-src/<id>/`（不进 web 包）；`public/plugins/<id>/` 只保留主程序内置的 `handwriting-lexicon`、`ocr-ensemble`、`ocr-log` |
| 强制程度 | 标"必须/禁止"的条目为硬约束，校验不通过会被市场拒绝（HTTP 422/413）；标"建议"的为最佳实践 |

### 1.3 与《OCR插件接入文档》的关系

| 关系 | 说明 |
| --- | --- |
| 定位 | 本文是《OCR插件接入文档》的**"打包发布"补充**，不是替代。插件的运行时行为（`handler.php`/`check.php` 契约、上下文、返回值）仍以该文档为准 |

| 增量内容 | 本文新增的只是"分发层"约束：目录/id 命名、zip 根层级布局、大小/文件数/扩展名限额、版本比对规则、提交前校验清单、打包命令 |
| 存量兼容 | 6 个存量插件**不改一行代码、不改 `plugin.json`、不升版本**，按现有目录直接打包即可入库（见 §8） |

## 2. 插件目录结构与命名规范

### 2.1 id 命名规则（硬约束）

插件 id 是市场、目录、包、索引四方的唯一标识，必须满足：

```
^[a-z0-9][a-z0-9-]{0,31}$
```

| 规则 | 说明 | 正例 | 反例 |
| --- | --- | --- | --- |
| 首字符 | 小写字母或数字 | `baidu-ocr`、`1ocr` | `-ocr`、`_ocr` |
| 其余字符 | 小写字母、数字、短横线 `-` | `mimo-v26-flash` | `qwen35_ocr`、`BaiduOCR`、`ocr.log` |
| 长度 | 1–32 位（首字符 + 最多 31 位） | `ocr-log` | 33 位以上的串 |
| 大小写 | 全小写，禁止大写 | `ocr-ensemble` | `OCR-Ensemble` |

> id 一经发布**不可更改**（索引以 id 为主键，改名等同于发布一个新插件）。

### 2.2 目录与文件结构

```
plugins-src/<id>/                  ← 打包源目录（仓库根下，不进 web 热更包），目录名必须 = id
├── plugin.json                     ← 必填：清单
├── handler.php                     ← 必填：执行脚本（文件名由 plugin.json.entry 指定）
├── check.php                       ← 可选：自检脚本（文件名由 plugin.json.check 指定）
├── shared.php / lib.php            ← 可选：公共 PHP，由 handler/check 手动 require
├── README.md / CHANGELOG.md        ← 可选：说明 / 变更记录
└── assets/                         ← 可选：小型静态资源（受白名单与限额约束）
    └── icon.png
```

> **双目录口径**：`plugins-src/<id>/` 是插件源码与打包源目录（**不进 web 热更包**）；`public/plugins/<id>/` 只保留主程序内置的 `handwriting-lexicon`、`ocr-ensemble`、`ocr-log`；**市场安装落盘目录为 `data/market-plugins/<id>/`**（安装/升级/卸载的唯一写根，App 热更只写 `public/`，天然零覆盖）。目录名 = id 的四处一致规则不变（见 §4.2、§6）。

### 2.3 必选 / 可选文件清单

| 文件 | 必选性 | 约束 |
| --- | --- | --- |
| `plugin.json` | **必选** | 位于目录根且全包唯一；JSON 合法；`id` = 目录名 |
| `handler.php`（或 `entry` 指定文件） | **必选** | 文件真实存在、以 `.php` 结尾；文件名与 `plugin.json.entry` 完全一致 |
| `check.php`（或 `check` 指定文件） | 可选 | 若 `plugin.json` 声明了 `check`，则文件必须存在；否则设置页不显示"API 链接测试" |
| 其它 `.php` / 资源 | 可选 | 受扩展名白名单、文件数（≤100）、解压后总量（≤20MB）、目录深度（≤3）约束 |

> 隐藏文件（`.` 开头）、`data/`、`../` 等一律不得进入发布包，详见 §4.5。

## 3. `plugin.json` 字段契约

> **本节完全沿用《OCR插件接入文档》§3。市场不新增任何必填字段。** 未列出的字段按该文档原规则处理，本文不作改动。

### 3.1 顶层字段（沿用原文档 §3.1）

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `id` | 是 | 小写字母/数字/短横线，1–32 位；**必须与目录名完全一致**，否则插件不会被加载 |
| `name` | 否 | 展示名，≤40 字，缺省用 id |
| `version` | 否 | 展示用，≤20 字，建议语义化版本（**发布到市场时必填，见下方说明**） |
| `description` | 否 | ≤200 字 |
| `author` | 否 | ≤40 字 |
| `capabilities` | 否 | 能力标签数组：`report.ocr`（识别引擎）/ `report.ocr.fusion`（融合，前端优先作为默认引擎）/ `report.ocr.log`（日志，按钮显示"查看日志"）。见 §6 白名单 |
| `entry` | 否 | 执行脚本文件名，默认 `handler.php`；必须存在且以 `.php` 结尾 |
| `check` | 否 | 自检脚本文件名，可选；不存在则设置页不显示「API 链接测试」 |
| `defaultEnabled` | 否 | 缺省 `true`；`false` 时首次安装默认停用 |
| `settings` | 否 | 配置项数组，见 §3.2 |

**关于 `version` 的说明（重要，避免误解为"新增必填项"）：**

- 契约层面 `version` 仍是**可选**字段，本文**不改变**这一点。
- 但市场发布的版本基线来自 `plugin.json.version`（架构文档 B.3 §5、§10），tag、索引 `version`、包名中的版本都由它派生。因此**凡要发布到市场的插件，实践中必须填写合法的语义化 `version`**——这是发布规范的要求，不是对 `plugin.json` 契约新增必填字段。纯本地插件仍可省略。

### 3.2 `settings` 配置项（沿用原文档 §3.2）

| 字段 | 说明 |
| --- | --- |
| `key` | 必填，字母开头，字母/数字/下划线，≤32 位，同一插件内唯一 |
| `label` | 设置页显示名称，≤40 字 |
| `type` | `text`（默认）/ `password` / `number` / `select` / `checkbox` / `textarea` / `multiselect` |
| `placeholder` | 输入框占位文字，≤120 字 |
| `hint` | 输入框下方说明，≤120 字 |
| `default` | 默认值（字符串；checkbox 用 `"1"` 表示默认勾选；multiselect 用逗号分隔的值） |
| `rows` | 仅 textarea，2–12，默认 4 |
| `options` | 仅 select / multiselect，`[{"value":"...","label":"..."}]`，value 必填 |
| `source` | 仅 multiselect；填 `ocrEngines` 时由后端自动生成"其它已安装识别插件"选项，无需手写 options |
| `min` / `max` / `step` | 仅 number，设置页渲染为输入框约束，后端保存时按范围校验 |

保存规则（后端统一处理，插件无需关心，详见原文档 §3.2）：

- `password`：回显 `********`，提交该占位值不覆盖原值。
- `checkbox`：保存为 `"1"` 或 `""`。
- `number`：空串原样保存，否则规范为数字字符串；声明 min/max 时越界拒绝。
- `multiselect`：前端提交数组，后端只保留清单允许的选项并用逗号拼串；`source: ocrEngines` 只允许其它声明 `report.ocr` 的插件。
- 其它：`text`/`select` ≤500 字，`textarea` ≤2000 字；只保存清单声明过的 key，未知 key 忽略。

### 3.3 市场展示字段从索引补充（不塞进 plugin.json）

架构文档明确"不另造清单、不膨胀 plugin.json 契约"。以下展示字段由 CI 写入 `plugins-index.json`，**插件作者无需也不得把它们加进 `plugin.json`**：

| 展示字段 | 来源 |
| --- | --- |
| `changelog` | tag 提交说明或 `CHANGELOG.md`（≤500 字） |
| `minSystemVersion` | 最低系统版本，如 `2.6.0`（低于时不显示升级按钮） |
| `releasedAt` | 发布时间，ISO 8601 |
| `package.*`（name/url/browserUrl/sha256/size） | CI 打包/上传后自动生成 |

> 索引的完整结构与示例见《打包工作流文档》§5，权威定义在《插件市场-架构设计》A.3.2。

## 4. zip 打包布局规范

> 来源：架构文档 A.3.4、A.5。手机端 `ZipInspector` 会逐条静态校验，任一违规返回 422（结构）/ 413（超限）。

### 4.1 标准布局

```
plugin-baidu-ocr-v1.3.0.zip          ← 文件名 = tag + .zip（仅用于展示）
├── plugin.json                       ← 必填，位于根，id/version 与索引、tag 一致
├── handler.php                       ← 必填，文件名 = plugin.json.entry
├── check.php                         ← 可选，文件名 = plugin.json.check
├── lib.php / shared.php              ← 可选，由 handler 手动 require
├── README.md / CHANGELOG.md          ← 可选
└── assets/*.png                      ← 可选，小型资源
```

### 4.2 硬性规则（必须全部满足）

| # | 规则 | 违反后果 |
| --- | --- | --- |
| 1 | **根目录直接是插件内容**，禁止再套一层 `<id>/` 目录（如 `baidu-ocr/plugin.json`） | 422：解析歧义，无法定位 plugin.json |
| 2 | 必须含且**只含一个** `plugin.json`，且位于 zip 根 | 422 |
| 3 | `plugin.json.id` 与目标目录名、索引 id、`package.name` 中的 id **四者一致** | 422 |
| 4 | 禁止出现 `data/`、`../`、绝对路径 `/`、盘符、反斜杠 `\`、空字节、符号链接、`.user.ini`、`.htaccess` | 422（zip-slip / 路径越界） |
| 5 | 扩展名必须在白名单内（见 §4.4） | 422 |
| 6 | 满足全部限额（见 §4.4） | 413 |
| 7 | `plugin.json.entry` 指向的文件真实存在且以 `.php` 结尾 | 422 |
| 8 | `capabilities` 全部在白名单内（见 §6） | 422 |

> 非内置插件源码在 `plugins-src/<id>/`，按该目录直接 `zip -r` 打包即可，无需改一行代码（架构文档 A.3.4 §7）。

### 4.3 扩展名白名单

```
.php  .json  .md  .txt  .css  .js  .png  .jpg  .jpeg  .webp  .svg
```

其余一律拒绝。特别注意不要混入 `.zip`、`.exe`、`.sh`、`.py`、`.env`、`.sqlite`、`.log`、Office 临时文件等。

### 4.4 限额

| 项 | 上限 | 说明 |
| --- | --- | --- |
| 单包体积（压缩后） | 5,242,880 字节（5 MB） | 下载时流式计数，超限立即中止；索引 `package.size` >5242880 直接拒绝 |
| 解压后总量 | 20 MB | 防"压缩炸弹" |
| 文件数 | 100 个 | 含所有文件，目录项一般不计 |
| 目录深度 | 3 层 | 以 zip 根为第 0 层，`assets/icon.png` 为 1 层 |

> 图片/大词典等大资源走独立下载，初版不纳入插件包（PRD §6.1）。

### 4.5 禁止项与 zip-slip 说明

| 禁止项 | 原因 |
| --- | --- |
| `data/` 路径或同名文件 | **禁止 `data/` 路径进包**：市场写入目标只能是 `data/market-plugins/<id>/`；包内禁带 `data/` 是为避免覆盖 data 下既有业务数据（数据库/图片/`plugins.json`/日志）并绕过安装器写根约束。`public/plugins/` 必备区由 web 包维护，市场只读、绝不写入 |
| `..` 路径段（如 `../evil.php`、`a/../../b.php`） | zip-slip 目录穿越，可写到插件目录外 |
| 以 `/` 或盘符开头的绝对路径 | 同上，解压目标不可控 |
| 反斜杠 `\` | 跨平台路径分隔符歧义，Windows 上可被解释为目录 |
| 空字节 `\0` | 截断路径绕过校验 |
| 符号链接 / 设备文件（Unix mode 标记） | 解压后可指向插件目录外 |
| `.user.ini` / `.htaccess` | Web 服务器配置注入 |
| 隐藏文件 / 隐藏目录（`.` 开头） | 易夹带 `.env`、编辑器缓存等敏感或不合规文件；保证包内容纯净 |

> 手机端解压后还会对每个文件做 `realpath()` 校验，必须仍位于 `data/market-plugins/.tmp-<id>-*` 目录内，否则整包拒绝并回滚（架构文档 A.5）。

## 5. 版本规范

### 5.1 语义化版本

- 格式：`X.Y.Z`（主版本.次版本.修订号，均为非负整数），如 `1.3.0`、`0.1.0`。
- 比对时容忍前缀 `v`/`V`，即 `v1.3.0` 与 `1.3.0` 视为相等；索引与 tag 统一使用**不带 `v` 前缀**的 `version` 值（`v` 只出现在 tag 名里）。
- 发布新版本必须**严格递增**：`compare(新, 旧) > 0`，否则不给升级按钮（架构文档 A.3.5）。
- 非内置插件首版索引版本 = 各自 `plugin.json.version`，以发布时实际版本为准（见 §8）。

### 5.2 与系统版本解耦

| 项 | 说明 |
| --- | --- |
| 插件版本 | 只认 `plugin.json.version`，由 `plugin-<id>-vX.Y.Z` tag 驱动发布 |
| 系统版本 | `web-v*` tag 驱动服务端热更（App v2.5 已在用） |
| 关系 | 两套 tag、两条流水线**完全解耦**：插件发版不需要系统发版。系统发版（`web-v*`）只带 `public/plugins/` 下的 3 个内置插件；其余插件源码在 `plugins-src/`，不进 web 包；市场升级副本在 `data/market-plugins/`，**不受系统更新影响**。同名 id 以市场副本为准（market 优先） |
| 兼容闸门 | 插件可声明 `minSystemVersion`（如 `2.6.0`）；手机端系统版本低于它时不显示升级按钮 |

### 5.3 预发布版本规则

- 允许预发布后缀：`X.Y.Z-<pre>`（如 `1.2.0-beta.1`）；`+` 后的构建元数据在比对时忽略。
- 排序规则：**预发布 < 正式版**，即 `1.2.0-beta.1 < 1.2.0`。
- 两个预发布会比较时按字符串序（`strcmp`）判定。
- 初版市场建议只发正式版；预发布用于内部测试，避免推给全体用户。

### 5.4 版本比对算法（与架构文档 A.3.5 完全一致）

```text
normalize(v):
    s = trim(v)
    s = 去掉开头的 v / V
    core, sep, pre = 按第一个 '-' 或 '+' 切分
    parts = explode('.', core)  →  取前 3 段，不足补 '0'，每段转 int（非数字按 0）
    return { core: parts, hasPre: sep != '' && pre != '', pre: pre }

compare(a, b):
    na = normalize(a), nb = normalize(b)
    逐段比较 na.core[i] vs nb.core[i]：大者返回 1，小者返回 -1
    三段全等时：
      两者都无预发布 → 0
      a 有 b 无   → -1        （1.2.0-beta.1 < 1.2.0）
      a 无 b 有   → 1
      都有       → strcmp(na.pre, nb.pre) 符号化
```

示例：`v1.10.0 > 1.9.0`、`1.2.0-beta.1 < 1.2.0`、`1.3.0 == v1.3.0`、`0.1.0 < 1.0.0`。

## 6. 提交前校验清单

> 开发者提交前逐项自查；CI 使用**同一份清单**（见《打包工作流文档》§4）。全部通过才可打 tag。

| # | 检查项 | 通过标准 | 对应拒绝码 |
| --- | --- | --- | --- |
| 1 | id 格式 | 匹配 `^[a-z0-9][a-z0-9-]{0,31}$`，全小写 | 400 |
| 2 | **四处 id 一致** | 目录名 = `plugin.json.id` = 索引 id = `package.name` 中的 id | 422 |
| 3 | JSON 合法 | `plugin.json` 可被 JSON 解析器解析，UTF-8 无 BOM | 422 |
| 4 | 唯一 plugin.json | 位于 zip 根，且全包仅一个 | 422 |
| 5 | 根层级 | zip 根直接是插件内容，未多套一层 `<id>/` | 422 |
| 6 | entry 存在 | `entry`（默认 `handler.php`）文件真实存在且以 `.php` 结尾 | 422 |
| 7 | check 一致 | 若声明 `check`，对应文件存在 | 422 |
| 8 | 能力标签白名单 | `capabilities` 全部 ∈ {`report.ocr`, `report.ocr.fusion`, `report.ocr.log`} | 422 |
| 9 | 扩展名白名单 | 所有文件扩展名 ∈ §4.3 列表 | 422 |

## 7. 打包实操命令

> 关键：**在插件目录内**打包（这样 zip 根才是插件内容），排除隐藏文件与 `data/`。以下以 `baidu-ocr` 从 `1.3.0` 打包为例。

### 7.1 使用 `zip`（本地/多数系统自带）

```bash
cd plugins-src/baidu-ocr

# 打包：根即当前目录内容；-x 排除隐藏文件、data/、常见垃圾文件
zip -r -9 ../../plugin-baidu-ocr-v1.3.0.zip . \
  -x '.*' \
     '*/.*' \
     'data/*' \
     'data/' \
     '*.log' \
     '__MACOSX/*'

cd ../../..
ls -lh plugin-baidu-ocr-v1.3.0.zip
```

### 7.2 使用 `jar`（JDK 自带，与历史 `.gitlab-ci.yml` 风格一致）

```bash
# jar 不写排除语法，需先准备一个只含合规文件的临时目录
STAGE=$(mktemp -d)
rsync -a \
  --exclude='.*' \
  --exclude='data/' \
  --exclude='*.log' \
  public/plugins/baidu-ocr/ "$STAGE/"

cd "$STAGE" && jar cf /tmp/plugin-baidu-ocr-v1.3.0.zip . && cd -
rm -rf "$STAGE"
```

### 7.3 打包后自查（建议每次执行）

```bash
ZIP=plugin-baidu-ocr-v1.3.0.zip

# 1) 结构：根层级是否直接是插件内容（应看到 plugin.json，而非 baidu-ocr/）
unzip -l "$ZIP" | head -30

# 2) 是否误带隐藏文件 / data/ / 非法扩展名
unzip -l "$ZIP" | grep -E '(^|/)\.|/data/|\.zip$' && echo '发现禁止项！' || echo '结构干净'

# 3) 体积（必须 ≤ 5242880 字节）
stat -c '%s bytes' "$ZIP"

# 4) 文件数与解压后总量
echo "文件数: $(unzip -Z1 "$ZIP" | wc -l)"
echo "解压后总量: $(unzip -Z1 "$ZIP" | xargs -I{} stat -c %s public/plugins/baidu-ocr/{} 2>/dev/null | awk '{s+=$1} END{print s}') bytes"

# 5) sha256（打 tag 后 CI 会重新算并写入索引，本地可用于比对）
sha256sum "$ZIP"
```

> CI 内的实际打包与哈希计算由 `.github/workflows/plugin-release.yml` 自动完成（见《打包工作流文档》§4），开发者本地打包主要用于自检和离线导入场景。

## 9. 常见错误与排查

| 现象 | 可能原因 | 排查/修复 |
| --- | --- | --- |
| 设置页看不到插件 | 目录名与 `id` 不一致 / JSON 非法 / `entry` 不存在 | 核对 §6 清单第 2、3、6 项 |
| 市场报 422「zip 结构不合规」 | 多套了一层 `<id>/` 目录 / 无 plugin.json / id 不一致 / 非法扩展名 / zip-slip | 用 §7.3 解包查看根目录，按 §4.2 逐条核对 |
| 市场报 413「包过大」 | 压缩后 >5MB 或解压后 >20MB / 文件数 >100 / 深度 >3 | 精简资源，大文件走独立下载；按 §4.4 核对 |
| 市场报 409「已是该版本 / 目标版本更低」 | 新版本未严格递增 | 按 §5.4 比对，确保 `compare(新, 旧) > 0` |
| 市场报 410「下载失败 / SHA256 不符」 | 索引 sha256 与实际包不符 | 确认 CI 重新计算哈希并写回索引；不要手工改包 |
| 手机端提示"本地较新" | 本地版本 > 索引版本 | 检查是否漏打 tag 或索引未更新 |
| 升级后密钥丢失（不应发生） | 误把 `data/plugins.json` 打进包或改动了配置键 | 包内禁止 `data/` 路径进包；安装器不写 `data/plugins.json`，市场仅写 `data/market-plugins/`；settings 的 key 保持稳定，新增项用 `default`；升级后可核对 state 文件哈希不变 |
| `check.php` 测试失败 | 密钥未配置 / 网络不通 / 证书缺失 | 按《OCR插件接入文档》§5、§8 排查 |
| 日志目录不可写 | `data/ocr-logs/` 权限不足 | 检查 Web 用户写权限（`ocr-log` 插件） |

> 运行时行为类问题（返回值、字段截断、融合调用等）不在本文范围，请查《OCR插件接入文档》§4、§8。
